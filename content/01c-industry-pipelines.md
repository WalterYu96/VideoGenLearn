# 专题：顶级视频生成团队的数据处理管线

> [!结论] 一句话
> 各家骨架基本一致：**切镜 → 叠加物处理 → 质量 / 运动过滤 → 语义去重 → 聚类均衡 → 稠密 caption → 分阶段数据**。真正拉开差距的是三处：**质量模型**（决定画质上限）、**caption 模型**（决定指令遵循上限）、**多任务数据构造**（决定参考 / 编辑等能力）。

> [!注意] 资料可得性（2026-11）
> 公开数据管线细节的只有 **Seedance 1.0**、**Wan 2.1**、**Kling-Omni** 三份技术报告。**Wan 3.0** 与 **MiniMax H3（海螺 3.0）**没有正式技术报告；**Seedance 2.0** 报告（arXiv 2604.14148）的二手资料只提到“多阶段管线、重视音画一致性”。下文以各家最近一份公开报告为准，推断内容会明确标注。

## 各团队管线详解

### Seedance（字节 Seed）

报告把数据流程分成三段：**多样性采集 → 多阶段清洗 → 离线打包**。

```flow
多样性采集 | 公开 + 授权数据，按主体 / 场景 / 动作 / 风格 / 运镜等属性规划，合规预筛
镜头切分 | 帧间差异或预训练检测器；3–12s，上限 12s，允许多镜头片段
叠加物矫正 | 规则 + 目标检测定位 logo / 水印 / 字幕，自适应裁剪
质量与安全过滤 | 模糊、抖动、低美学、构图差、近乎静止；色情 / 暴力 / 儿童安全 / 裸露
语义去重 | 自研视频 embedding 聚类，每簇保留质量最高的一条
分布均衡 | 头部类别降采样，长尾上采样并定向补采
Caption | Tarsier2 微调（冻视觉塔、全量调 LLM），中英双语稠密描述
离线打包 | BMF + Ray，预计算 caption 与 VAE latent
```

- **分阶段数据**：256px 图视频联合（3–12s，12fps）→ 640px → 24fps；CT 阶段 I2V 占比从 20% 提到 40%，用美学打分器和光流运动评估挑“双高”子集，并混用长短 caption；SFT 只用几百个类别、人工核验 caption 的少量片段，分类别训练后做模型融合。
- **Prompt 改写器**：Qwen2.5-14B 做 SFT + LoRA-DPO，把用户输入改写成训练 caption 的分布。
- **Seedance 1.5 pro / 2.0**：走向音视频联合生成。二手资料称 2.0 的管线“多阶段、重视音画一致性”，按 [第 5 章](#/reference) 的经验，至少需要：只保留音画对应的片段、标注对白 / 说话人 / 语种 / 音效 / 音乐（推断）。

### Wan（阿里通义）

Wan 2.1 的特点是**过滤器种类多、分级细**，并给出了不少可直接借鉴的数字。

```flow
四步基础清洗 | 约剔除 50% 初始数据
文字与安全 | OCR 文字占比过滤；内部 NSFW 模型
画面瑕疵 | 水印 / Logo 检测（训练时裁掉）、黑边裁剪、过曝分类器、模糊分
AIGC 检测 | 合成图检测器，合成数据超过 10% 就有害
视觉质量 | 聚 100 簇 → 每簇人工 1–5 分 → 训练专家模型全量打分
运动质量 | 6 档：静止和纯运镜降权，低质与抖动剔除
视觉文字数据 | 数亿张合成文字图 + 真实文字图（Qwen2-VL 生成描述）
稠密 caption | 自研模型，加入 OCR、计数（Grounding DINO）、名人识别（TEAM）
后训练数据 | 美学前 20% 图片 + 数百万简单 / 复杂运动视频，平衡 12 类
```

- **规模**：数十亿视频和图片；分辨率门槛随阶段提高（256 → 480 → 720px）。
- **Wan 2.2 / 2.7 / 3.0**：2.2 的报告与 GitHub 主要讲 MoE 与 VAE；Wan 3.0 官方宣传“单次 30s、可吃文档 / 网页”，但没有数据管线细节。从能力推断，3.0 需要更长片段的多镜头数据与“文档 → 剧本 → 分镜”的配对数据（推断）。

### Kling（快手）

Kling-Omni 的重点从“清洗原始视频”转向**构造多任务数据**，数据系统分为采集、处理、基础设施三部分。

```flow
采集 | 大规模真实数据 + 自研 embedding 模型挖掘互联网跨模态样本
合成 | 自研编辑模型 / 视频理解模型生成数据；参考生视频用“自动反向合成”
第一层：基础过滤 | 分辨率 / 时长门槛、帧级 + 时序指纹去重、音画损坏检测、NSFW
第二层：时序质量 | 模糊 / 抖动 / 压缩噪声打分；剔除突兀转场、镜头不连贯、动作语义密度低
第三层：跨模态对齐 | caption–视频一致性、参考保真度、编辑指令一致性、人物身份一致性
分阶段 | 预训练（T2V 为主混 I2V）→ CT（参考、编辑、理解）→ quality-tuning → DPO
```

- **相关报告补充**：[Kling-MotionControl](https://arxiv.org/html/2603.03160v1) 按整体质量分、运动幅度与流畅度、主体一致性过滤；KlingAvatar 2.0 搭了自动标注管线，为多人数据生成逐角色视频 mask。
- **Kling 3.0**：原生 4K / 60fps、单次最多 6 个镜头切换、5 语种口型同步。这要求多镜头长片段 + 分镜 caption + 多语种对白标注（推断）。

### MiniMax H3（海螺 3.0）

- 33B，4–15s / 24fps，原生立体声；第三方资料称 2026-08 公布了权重。
- **没有技术报告**：第三方资料说完整报告“承诺发布但尚未发布”，训练数据规模、过滤方法均未披露。
- 从能力推断：音画联合生成需要配对音频数据与音频 caption；24fps、15s 意味着训练片段时长覆盖到 15s 左右（推断）。

## 各家侧重点

- **Seedance**：**多样性与均衡**优先。从采集阶段就按属性分布规划，语义去重控制重复；caption 投入大（人工标注 + 微调 Tarsier2）；分阶段数据路线写得最完整。
- **Wan**：**过滤器多、分级细**。可借鉴的数字：合成数据超过 10% 有害、基础清洗剔除约 50%、运动分 6 档、100 簇 + 人工打分训练专家模型。
- **Kling**：**多任务数据构造**。合成数据、反向合成、跨模态对齐校验，支撑编辑 / 参考 / 理解一体的全能模型。
- **MiniMax H3 / Wan 3.0 / Seedance 2.0**：缺少一手资料。音视频联合生成是共同方向，新一代管线大概率加入**音画同步质量过滤**和**配对音频 caption**（推断）。
- **开源团队**：Waver 与 Open-Sora 2.0 的阈值和维度最具体，适合作为自建管线的起点。

## 共同的管线骨架

```flow
多样性采集 | 按属性分布规划 + 合规预筛
镜头切分 | ≤ 10–12s，转场 / 不连贯二次校验
叠加物处理 | OCR、字幕、水印、Logo 检测后裁剪或剔除；黑边裁剪
质量过滤 | 模糊、抖动、压缩、过曝、美学、AIGC 合成检测、安全
运动分级 | 光流：静止降权、抖动剔除、高运动子集留给后期
语义去重 | 视频 embedding 聚类 / 指纹
聚类均衡 | 头部降采样、长尾上采样
稠密 caption | 静态 + 动态 + 运镜，长短多版本，中英双语；音频 caption
分层训练数据 | 低分预训练 → 高分 CT → 人工精选 SFT → 偏好对齐
```
