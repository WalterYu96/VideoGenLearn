# 4.2 RL：奖励模型与偏好优化

> [!结论] 本节结论
> 视频后训练的 RL 阶段由两部分组成：**奖励**（人工偏好或奖励模型）和**优化算法**（离线 DPO、奖励反传、在线 GRPO / NFT）。公开报告里的主流做法是：**先用人工 GSB 偏好对做 DPO，打好起点；再用多维奖励模型做在线 RL**（HunyuanVideo 1.5）。成本最敏感的团队只做 DPO（Kling-Omni）。效果上限取决于奖励模型，最大的风险是奖励作弊和运动坍缩（视频越训越不动）。一份 2026 年的系统性报告给出的量级是：RLHF 让 GSB 提升 31%，Prompt 改写器 RL 再提升 20%（[来源](https://arxiv.org/abs/2604.25427)）。

```flow
偏好数据 | 当前模型多 seed 采样，按维度做 GSB 标注
奖励模型 | 对齐 / 画质 / 运动 / 物理 / 音画同步，分维度输出
离线 DPO | Flow-DPO，常数 β，修掉运动伪影
在线 RL | MixGRPO / 单步 SDE GRPO / DiffusionNFT，多奖励加权
防作弊 | 监控运动幅度、多奖励制衡、奖励模型迭代、人工抽检
Prompt 改写器 RL | 冻结生成器，GRPO 训练 LLM 改写器
```

> [!提示] 和 4.A 专题的分工
> 本节面向通用视频生成模型，讲选型和配方。Flow-DPO、NFT 等方法的逐步推导，以及在 33B 音视频模型上的落地方案，见 [4.A MiniMax-H3 后训练专题](#/h3-rl)。前后章节：[4.1 SFT](#/post-sft)、[4.3 蒸馏](#/post-distill)、[4.4 OPD](#/post-opd)。

## 奖励模型

### 奖励维度与代表模型

| 维度 | 代表模型 / 做法 | 要点 |
|---|---|---|
| 画质 + 运动 + 文本对齐 | **VideoReward**（VideoAlign，快手） | 18.2 万条人工三元组，覆盖 12 个视频模型、1.6 万 prompt；Qwen2-VL-2B 骨干；三个维度各用一个专用 token 输出分数（[来源](https://arxiv.org/html/2501.13918)） |
| 画质 + 对齐 + 物理常识 | **VideoScore2**（TIGER-Lab） | 先写思维链再打分；2.7 万条人工标注视频（VideoFeedback2），SFT 后再用 GRPO 训练；可作为 Best-of-N 奖励（[来源](https://arxiv.org/abs/2509.22799)） |
| 多维可解释 | **VisionReward**（智谱） | 分层细粒度判断后线性加权；视频偏好预测准确率比 VideoScore 高 17.2%（[来源](https://arxiv.org/abs/2412.21059)） |
| 理解 + 生成统一 | **UnifiedReward** | 一个模型同时支持成对排序和单点打分，图像和视频都能评（[来源](https://arxiv.org/abs/2503.05236)） |
| 图像美学 / 偏好 | **HPSv3** | 108 万图文对、117 万成对比较（HPDv3），VLM 骨干 + 带不确定度的排序损失（[来源](https://arxiv.org/abs/2508.03789)）；视频上常按帧打分再聚合（LongCat-Video 取得分前 30% 帧的平均，[来源](https://arxiv.org/html/2510.22200)） |
| 几何 / 相机一致 | **VGGRPO**（Google） | 在 latent 上预测几何，奖励相机平滑和重投影一致，不用解码 RGB；奖励计算从 54.73 s 降到 41.33 s（[来源](https://arxiv.org/html/2603.26599)） |
| 音画同步 | **SyncReward**、**VA-Judger** | 8 万条同步评分；报告称 Synchformer 等专项指标和人类判断差距明显（[来源](https://arxiv.org/html/2610.16338)）。VA-Judger 是思维链式全模态评审（[来源](https://sharelab-sii.github.io/VA-Judger/)） |
| 通用 VLM 评审 | 直接提示大模型打分（VLM-as-judge） | 零训练成本，适合做评测和数据筛选；作训练奖励时噪声大、慢，一般要先在自家偏好数据上微调成专用 RM |

### 成对 vs 打分

| 形式 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| 成对偏好（BT / 带平局的 BTT） | 标注一致性高，能捕捉细微差别；VideoAlign 实验中 BT 一直优于分数回归（[来源](https://arxiv.org/html/2501.13918)） | 只给相对分，跨 prompt 不可比 | 训练 RM、DPO 数据 |
| 单点打分（回归 / 思维链打分） | 直接给出奖励值，在线 RL 好用 | 同一组样本得分挤在一起，归一化后会放大噪声 | GRPO / NFT 的在线奖励 |
| 组内两两比较（Pref-GRPO） | 用组内胜率当奖励，避免“虚假优势” | 每组要做 $O(G^2)$ 次比较 | 在线 RL 中替代单点分（[来源](https://arxiv.org/abs/2508.20751)） |

VideoAlign 的两条经验值得照搬：**保留平局标注**（BTT，θ=5.0），以及**各维度分开输出**，不要混成一个总分（[来源](https://arxiv.org/html/2501.13918)）。BTT 公式见 [4.A 的 3.6 节](#/h3-rl)。

> [!经验] 奖励模型的坑
> - **文本对齐最难**：2026 系统性报告中对齐维度提升最小，作者归因于对齐 RM 不够强（[来源](https://arxiv.org/abs/2604.25427)）；DanceGRPO 在视频上干脆不用 TA 奖励，因为它“明显不稳定”（[来源](https://arxiv.org/html/2505.07818)）。
> - **运动质量难判**：HunyuanVideo 1.5 明确说现有 RM 难以区分细粒度运动质量，所以先用人工偏好做 DPO（[来源](https://arxiv.org/html/2511.18870v2)）。
> - **分维度标注要加约束**：Seedance 1.0 每次只按一个维度挑最好 / 最差，并要求胜出方在其他维度上不能更差（[来源](https://arxiv.org/html/2506.09113v2)）。

## 偏好优化方法族

| 方法 | 类别 | 核心思想 | 优点 | 缺点 | 代表应用 |
|---|---|---|---|---|---|
| [Diffusion-DPO](https://arxiv.org/abs/2311.12908) / [Flow-DPO](https://arxiv.org/abs/2501.13918) | 离线偏好 | 好样本的去噪误差相对参考模型降得比坏样本多 | 不用在线采样，成本接近 SFT，可直接接 GSB 标注 | 受限于离线数据，数据会过时 | Kling-Omni、HunyuanVideo 1.5 T2V |
| [OnlineVPO](https://arxiv.org/abs/2412.15159) | 在线 DPO | 用视频 RM 在线给当前模型的样本排序，课程式更新参考模型 | 数据 on-policy | 依赖 RM 质量 | 开源视频扩散模型 |
| ReFL / 奖励反传 | 可微奖励 | 训练时模拟推理，预测 $x_0$，对可微 RM 求梯度直接最大化 | 信号稠密，收敛快 | 显存高，必须可微，容易作弊 | Seedance 1.0（主模型和超分模型都用） |
| [Flow-GRPO](https://arxiv.org/abs/2505.05470) | 在线 RL | ODE 转等边缘分布的 SDE 引入随机性，组内归一化优势 | 不需要可微奖励，任何打分都能用 | 要存轨迹、每步算似然，最贵 | 学术基线（SD3.5-M 上 GenEval 63%→95%） |
| [DanceGRPO](https://arxiv.org/abs/2505.07818) | 在线 RL | GRPO 统一用于扩散 / RF、图像 / 视频；组内共享初始噪声；随机丢弃 40% 时间步 | 首个在大视频模型上跑通 | 64 张 H800 训 T2V | HunyuanVideo：MQ +181%，VQ +56% |
| [MixGRPO](https://arxiv.org/abs/2507.21802) | 在线 RL | 只在滑动窗口内做 SDE 采样和优化，窗口外用 ODE（可用高阶求解器） | 训练时间比 DanceGRPO 少近 50%（Flash 版再少 71%） | 窗口外的步不优化 | HunyuanVideo 1.5（I2V / T2V） |
| [TempFlow-GRPO](https://arxiv.org/abs/2508.04324) | 在线 RL | 在指定分支点集中随机性，实现时间步级信用分配；按噪声水平加权 | 早期关键步获得更多优化 | 主要在 T2I 上验证 | — |
| 单步 SDE GRPO（[Flash-GRPO](https://arxiv.org/abs/2605.15980)、[2604.25427](https://arxiv.org/abs/2604.25427)） | 在线 RL | 每组只在同一时刻做一步 SDE（iso-temporal grouping），修正时间步相关的梯度尺度，只用终点奖励 | 成本低，作者称低预算下优于全轨迹训练 | 每次只训一步，依赖时间步采样 | LongCat-Video（16 步中只在前 6 步内选一步做 SDE） |
| [DiffusionNFT](https://arxiv.org/abs/2509.16117) / [RVM](https://arxiv.org/abs/2608.23664) | 前向过程 RL | 正负样本对比，把奖励折进 flow matching 损失；不需要似然和轨迹 | 不需 CFG，采样器任选，作者称比 FlowGRPO 高效最多 25 倍 | 比 GRPO 新，大规模视频验证少 | veRL-Omni 的 H3 配方；RVM 在 Wan2.1-1.3B 上 VBench 最高 |
| [OmniNFT](https://arxiv.org/html/2605.12480) / [AV-GRPO](https://arxiv.org/html/2609.29816) | 音视频联合 | 按模态分配优势值，视频奖励只训视频分支、音频奖励只训音频分支 | 解决“画面好、声音差”时信号相互抵消 | 依赖双塔结构 | LTX-2 / LTX-2.3 |

几个关键公式（推导见 [4.A](#/h3-rl)）：

$$\mathcal{L}_{\text{Flow-DPO}}=-\log\sigma\Big(-\tfrac{\beta}{2}\big[(\|v^w-v_\theta(x^w_t)\|^2-\|v^w-v_{\text{ref}}(x^w_t)\|^2)-(\|v^l-v_\theta(x^l_t)\|^2-\|v^l-v_{\text{ref}}(x^l_t)\|^2)\big]\Big)$$

$$A_i=\frac{r_i-\operatorname{mean}(r_{1..G})}{\operatorname{std}(r_{1..G})}\quad\text{（GRPO 组内优势）}$$

> [!注意] Flow-DPO 的 β 用常数
> VideoAlign 对比了时间步相关的 $\beta_t=\beta(1-t)^2$ 和常数 β：常数 β 在各个 β 值下都更好；用 $\beta_t$ 会出现奖励作弊，画质和运动胜率高，但文本对齐反而不如预训练模型（[来源](https://arxiv.org/html/2501.13918)）。

> [!经验] 从各家配方能看出的规律
> 1. **人工偏好打底**：HunyuanVideo 和 Kling 都先用人工偏好做 DPO，原因是 RM 判不准运动。
> 2. **多 RM 制衡**：没有一家只用一个奖励。LongCat 和 Seedance 都用画质 / 运动 / 对齐三类 RM，单一奖励更容易被作弊。
> 3. **压 rollout 成本**：Kling 因成本放弃 GRPO，LongCat 只在一步上做 SDE，Cosmos 只采 20 步，Seedance 1.5 专门优化 RLHF 基础设施。
> 4. **RM 要迭代**：Seedance 1.0 做 RM 与生成器多轮交替，称比在线更新 RM 更稳。

## Prompt 改写器 RL

冻结视频生成器，只训练把用户短 prompt 改写成训练 caption 分布的 LLM。奖励来自生成结果。

| 工作 | 基座 | 训练方式 | 奖励 |
|---|---|---|---|
| [RePrompt](https://arxiv.org/abs/2505.17540)（T2I） | LLM | RL，带显式推理的结构化改写 | 人类偏好、语义对齐、构图三类 RM，不需人工标注 |
| Seedance 1.0 | Qwen2.5-14B | 全参 SFT → LoRA DPO（正确 / 错误改写对，治幻觉） | 偏好对（[来源](https://arxiv.org/html/2506.09113v2)） |
| Kling-Omni | MLLM | SFT（学会思考过程）→ RL | 事实正确、内容丰富、语义合理、与高质量训练数据相似（[来源](https://arxiv.org/html/2512.16776v1)） |
| 2026 系统性框架 | LLM | GRPO，带 KL 惩罚 | 文本-视频对齐 + 视频美学 + 格式 / 长度结构奖励；GSB 再 +20%（[来源](https://arxiv.org/abs/2604.25427)） |
| Waver | GPT-4.1 等现成 LLM | 不训练，只写系统提示 | —（[来源](https://arxiv.org/html/2508.15761v2)） |

> [!提示] 为什么改写器 RL 性价比高
> 改写器的 rollout 是一次 LLM 生成加一次视频生成，不需要对视频模型反传，也不会破坏生成器。用户 prompt 越短，收益越大。

## 工程要点

### 成本与内存

| 问题 | 做法 | 依据 |
|---|---|---|
| rollout 贵 | 在 480p、短时长或少步模型上做 RL，再迁移；训练时用少步采样，推理保持原步数 | Flow-GRPO 的 Denoising Reduction；DanceGRPO 视频 25 步；Flash-GRPO 称 14B 模型 GRPO 单次实验需“数百 GPU 天”（[来源](https://arxiv.org/abs/2605.15980)） |
| 轨迹内存 | 只优化部分时间步：滑动窗口（MixGRPO）、单步 SDE（Flash-GRPO / LongCat）、随机丢弃时间步（DanceGRPO） | 见上表 |
| 逐步算似然显存不够 | 把轨迹概率拆成逐步条件概率，分段反传、累积梯度 | Cosmos-Predict2.5（[来源](https://arxiv.org/html/2511.00062v2)） |
| 奖励计算慢 | 奖励放在 latent 上算，避免反复解码 | VGGRPO |
| 不想存轨迹 / 不想开 CFG | 用 DiffusionNFT / RVM 一类前向过程方法 | [DiffusionNFT](https://arxiv.org/abs/2509.16117) |
| 大模型全参 | LoRA；参考模型 = 关闭 adapter 的基座 | [4.A](#/h3-rl) |

### KL、参考模型与稳定性

- **KL / 参考模型**：Flow-GRPO 保留 KL；2026 系统性框架和单步 SDE 方案去掉了 KL，改靠多奖励和正则防作弊（[来源](https://arxiv.org/abs/2604.25427)）；Cosmos 用扩散损失正则代替 KL（[来源](https://arxiv.org/html/2511.00062v2)）；OnlineVPO 按课程更新参考模型（[来源](https://arxiv.org/abs/2412.15159)）。
- **组内共享初始噪声**：DanceGRPO 发现组内初始噪声不同会导致奖励作弊（[来源](https://arxiv.org/html/2505.07818)），LongCat 也这样做。
- **时间步相关的梯度尺度**：高噪声、小步长时梯度消失或尺度不一致。LongCat 给策略损失乘 $\sqrt{t/(\Delta t(1-t))}$ 重新加权，Flash-GRPO 做 temporal gradient rectification。
- **优势归一化**：组内分数挤在一起时，除以组内 std 会放大噪声。LongCat 改为除以所有组的最大 std，Pref-GRPO 改用组内胜率。
- **奖励饱和**：多奖励里已饱和的分量会主导或带偏方向。TaRoS 按组内稀疏度自适应降低饱和分量的权重（[来源](https://arxiv.org/abs/2511.19356)）。
- **超参起点**：公开且有出处的只有 LongCat 的 lr 1e-4、G=4、500 次迭代（[来源](https://arxiv.org/html/2510.22200)）和 veRL-Omni H3 配方的 LoRA rank 64、每 prompt 16 个样本、训练 10 步采样（[来源](https://vllm.ai/blog/2026-11-06-verl-omni-v0-3-0)）。β、学习率都需要扫参。

### 奖励作弊与运动坍缩

| 现象 | 应对 | 依据 |
|---|---|---|
| 奖励一直涨，画面先变糊，再出网格伪影，最后坍缩 | 奖励模型与生成器交替更新，用真实视频偏好锚定 | [CoRe](https://arxiv.org/html/2609.36245)（数字未在本节复核，见 [4.A](#/h3-rl)） |
| 运动幅度骤降，但“平滑度”“一致性”指标上升 | 每组掺入少量外部真实 / 强模型视频 | [GraftOOD](https://arxiv.org/html/2610.13470)：Wan2.1-1.3B dynamic degree 4.86→44.41，HPSv3 8.10→7.32 |
| 单一奖励被钻空子 | 多奖励加权；运动奖励单列；文本对齐不稳就先不用 | LongCat、DanceGRPO |
| 专项指标高，人类评分低 | 选 RM 时先做 Best-of-N 对照，看人评是否同步提升 | [SyncReward](https://arxiv.org/html/2610.16338) |

> [!注意] 必须监控的指标
> 不要只看奖励曲线。每个 checkpoint 至少同时看：训练奖励、**未参与训练的 RM**、运动幅度（VBench dynamic degree 或光流）、人工抽检。训练出的模型单次生成必须超过基座的 Best-of-N，否则训练没有意义。

### 评测

| 方式 | 用途 | 注意 |
|---|---|---|
| [VBench](https://arxiv.org/abs/2311.17982) / [VBench-2.0](https://arxiv.org/abs/2503.21755) | 自动化回归：运动幅度、时序一致、语义 | 静止视频在一致性类指标上天然高分，要和 dynamic degree 一起看 |

| GSB 人评 | 最终决策：Good / Same / Bad，分维度标注 | HunyuanVideo 1.5 用 300 条 prompt、100+ 评审（[来源](https://arxiv.org/html/2511.18870v2)）；Kling-Omni 用 500+ 条（[来源](https://arxiv.org/html/2512.16776v1)） |

## 选型建议

| 场景 | 建议 |
|---|---|
| 刚开始做，有标注预算 | 多 seed 生成 → 分维度 GSB → LoRA Flow-DPO（常数 β）；同时把标注拿去训 RM |
| 有可靠 RM、想继续提升 | 在线 RL：资源紧选 DiffusionNFT 或单步 SDE GRPO；要和学术基线对齐选 MixGRPO |
| 有可微的强 RM、显存充足 | ReFL 式奖励反传（Seedance 1.0 路线），注意 RM 迭代 |
| 音视频联合模型 | 按模态拆分奖励和优势值；同步奖励优先用专门训练的 RM（SyncReward），不要直接用 Synchformer |
| 指令遵循差 | 先做 Prompt 改写器 RL，便宜、风险低 |
| 资源极紧 | 只做 DPO + 改写器；用 Best-of-N 作基线 |
