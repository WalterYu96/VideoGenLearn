# 4.1 SFT：监督微调

> [!结论] 本节结论
> 视频模型的 SFT 是**小而精的数据 + 小学习率 + 早停 + 多模型融合**。数据量从几千条（Kandinsky 5.0 约 2.8 千条视频）到几十万条（Seaweed-7B 约 70 万条）不等，靠人工精挑和类别均衡保证质量，而不是靠数据量。它主要改善美学、色彩和运动稳定性，同时给后面的 RL 准备一个稳定的**参考策略**。训练太久会过拟合，提示词遵循能力和运动质量都会下降。多家报告（Seedance 1.0、Movie Gen、Step-Video、Waver、Kandinsky 5.0）都用了“分数据子集各自 SFT，再做权重平均”的方法。

## SFT 在后训练里的定位

```flow
预训练 | 海量数据，学“能生成”
CT（中训练） | 数据量约为预训练的 1/5–1/10，做质量退火、能力扩展和任务注入
SFT | 几千到几十万条人工精选数据，学“生成得好看”
偏好 / RL | 以 SFT 模型为起点和参考，修正结构、运动和对齐问题
```

| | 预训练 | CT（[中训练](#/midtraining)） | SFT | RL（[4.2](#/post-rl)） |
|---|---|---|---|---|
| 数据规模 | 数亿到数十亿 | 百万级（HunyuanVideo 1.5 每个任务约 100 万） | 千到十万级，个别到 70 万 | 万级 prompt，加上模型自己的采样 |
| 数据来源 | 自动过滤后的真实数据 | 高分子集 | **人工核验**的真实数据，少量合成数据 | 模型自己生成，再由奖励模型或人工打分 |
| 损失函数 | flow matching / 扩散 MSE | 同预训练 | **同预训练** | 奖励 / 偏好目标 |
| 学习率 | 最大 | 逐步退火 | 很小，或沿用预训练末期的值 | 更小（Seaweed DPO 只有 1e-7） |
| 主要收益 | 覆盖面和物理常识 | 画质上限、新任务 | 美学、色彩、风格统一 | 结构、运动、文本对齐 |

SFT 的损失和预训练一样，比如 rectified flow 的写法是 $\mathcal{L}=\mathbb{E}_{t,x_0,\epsilon}\|v_\theta(x_t,t,c)-(\epsilon-x_0)\|^2$。所以 SFT 和预训练的差别**全在数据和超参数上**。

- **SFT 不是用来解决对齐问题的**。2026-04 的一篇系统性后训练报告明确说，SFT 不是为了完全解决对齐或优化主观质量，它的作用是建立“稳定、结构良好的参考策略”，同时扩大 RLHF 的探索空间（[来源](https://arxiv.org/html/2604.25427)）。
- **SFT 会损害运动，需要 RL 补救**。Seaweed-7B 发现 SFT 后结构和运动变差，才加了 DPO 来修（[来源](https://arxiv.org/html/2504.08685)）。
- **SFT 是 RL 的起点**。HunyuanVideo 1.5 从“选定的高质量 SFT checkpoint”采样候选视频，做 GSB 标注后再进行 DPO 和在线 RL（[来源](https://arxiv.org/html/2511.18870v2)）。Seaweed 的 DPO 用固定的 SFT 模型作参考模型（[来源](https://arxiv.org/html/2504.08685)）。

## 数据构建

### 高质量片段筛选标准

| 维度 | 公开报告里的标准 | 来源 |
|---|---|---|
| 美学 / 构图 | 色彩和谐、光照、主体突出、空间布局；三分法、景深层次；背景不杂乱、主体完整 | HunyuanVideo、Emu |
| 光照 / 色彩 | 侧光（自然光或棚拍光）；色彩鲜明但不过饱和；避免平光和过曝 | Movie Gen、Emu |
| 运动 | 运动非平凡、无抖动；运动速度、动作完整性、运动模糊；复杂运动单独人工挑 | Movie Gen、HunyuanVideo、Waver |
| 清晰度 | Waver 只保留 2K/4K 素材；Step-Video 人工检查清晰度 | Waver、Step-Video |
| 干净程度 | 无后期特效、叠加文字、水印、字幕；无突兀转场 | Movie Gen、Step-Video |
| 小主体 | 用检测器剔除主体过小的片段 | Movie Gen |

**常见流程**：自动过滤（宽进）→ 概念 / 类别均衡 → 通才标注员初筛（重召回）→ 专家精筛（重精度，要求一致通过）。Emu、Movie Gen、Kandinsky 5.0 都是这个结构。各阶段的过滤算子见 [第 1 章](#/data) 和 [头部团队数据管线](#/data-industry)。

### Caption

- **人工核验或精修是标配**：Seedance 1.0、Step-Video、Movie Gen 都做了。Movie Gen 在 LLaMa3-Video 生成的 caption 上，由人工补充运镜、表情、主体和背景、运动细节、光照，另外标注 6 类运镜和机位。Step-Video 特意补上运镜信息。
- **caption 分布要和推理时一致**：推理时用户输入会先经过 Prompt 改写器，改写成训练 caption 的分布（Seedance、Kling-Omni 都这么做）。所以 SFT caption 的风格要和改写器的输出风格一致（推断）。
- **指令式 caption**：I2V 和编辑任务的 caption 描述的是**相对首帧或参考的变化**（HunyuanVideo 1.5 CT、Kling-Omni）。

### 类别均衡

| 做法 | 代表 |
|---|---|
| 预先定义数百个类别（风格、运动类型等），每类定向收集 | Seedance 1.0 |
| 按动作 / 表情分类体系，用文本 kNN 和视频 kNN 检索均衡子集 | Movie Gen |
| 12 个大类 | Wan 2.1 |
| 按 captioner 给出的主体类别均衡，数据量减半 | SkyReels-V2 |
| 用 VLM 分 9 个领域，每个领域单独训练再融合 | Kandinsky 5.0 |
| 簇内按到质心的距离过滤 | Step-Video |

### 合成数据、多镜头与音画

- **合成数据**：Waver 用自家模型把高质量图片素材做 I2V，生成美学和超现实视频。每条必须两人以上一致通过，并和真实数据保持平衡，防止模型风格偏向合成（[来源](https://arxiv.org/html/2508.15761)）。Wan 2.1 在预训练阶段发现合成数据比例超过 10% 有害（见 [头部团队数据管线](#/data-industry)）。在 SFT 里，合成数据应作为少量补充。
- **音画**：Movie Gen Audio 和 Seedance 1.5 pro 都在高质量音视频数据上做 SFT，但都没有公开筛选细节。按 [第 5 章](#/reference) 的经验，至少要保证音画对应、对白和说话人标注准确（推断）。
- **多镜头**：没有找到公开报告专门描述多镜头 SFT 数据。Seedance 1.0 在预训练阶段就允许多镜头片段；SFT 阶段可以按镜头数单独设一个类别做均衡（推断）。

## 训练技巧

| 项目 | 公开做法 | 建议 |
|---|---|---|
| 学习率 | Waver 5e-6（CT 1e-5）；Kandinsky 图像 1e-5（预训练 1e-4）；Seaweed 沿用预训练末期的学习率；Seedance“小于预训练” | 取预训练峰值的 1/10–1/20，或直接沿用退火末期的值 |
| batch | Kandinsky 64（预训练 4096）；Movie Gen“相对较小” | 小 batch，多步 |
| 步数 / 早停 | Emu ≤ 1.5 万步；Kandinsky 约 1 万步后过拟合；Waver 2 个 epoch；Seedance 和 Seaweed 都强调早停 | 每隔固定步数做小规模人工评测，loss 不能作为停止依据（Emu 停训时 loss 仍在下降） |
| checkpoint 选择 | Step-Video：等梯度范数达到峰值、回落之后再选 | 同时监控梯度范数和评测指标 |
| 全参 vs LoRA | 公开报告的主模型 SFT **都是全参**（Kandinsky 明确写了“独立全参微调”） | 主线用全参；资源有限、只调风格或做实验时用 LoRA，配置参考 [H3 专题](#/h3-rl) |
| EMA | Kandinsky 5 秒模型最好的是 EMA checkpoint；Step-Video 认为模型平均优于 EMA | 两者可以同时用：每个子模型保留 EMA，最后再平均 |
| 权重融合 | Seedance（分类别）、Movie Gen（不同数据、超参、起点）、Step-Video（不同 SFT 数据）、Waver（7–10 个模型）、Kandinsky（9 个领域均匀平均） | 见下 |
| 加大精品数据权重 | Seaweed：5 万条最好的数据加大权重 | 金字塔式数据：大量“好”数据 + 少量“极好”数据加权 |
| 图视频联合 | Waver、Kandinsky、Wan 都混入了图片 | 保留一部分高美学图片，稳住画质 |

**权重融合**（model soup）是视频 SFT 里最一致的技巧：

$$\theta_{\text{soup}}=\sum_{k=1}^{K} w_k\,\theta_k,\quad \sum_k w_k=1$$

- 每个子模型 $\theta_k$ 在一个类别、领域或数据版本上训练，**必须从同一个起点出发**，否则不能直接平均。
- 权重用均匀平均就够了（Kandinsky 视频）。Kandinsky 图像实验里，按数据量平方根加权和均匀平均都最好。
- 收益来源：单个领域模型容易过拟合、出伪影，平均后又稳又好（Kandinsky）。Waver 的数据是融合后运动 +5%，画质 +2%，指令遵循 +1%。

## 和 RL 的衔接

- **SFT 产出的就是 RL 的参考策略和初始化**。DPO 的参考模型、GRPO 的初始策略和采样来源，通常都是 SFT checkpoint（HunyuanVideo 1.5、Seaweed）。
- **不要把 SFT 训到最好看为止**。SFT 收得越紧，生成多样性越低，RL 组内样本的差异越小，优势估计就越弱。系统性后训练报告说 SFT 要“扩大 RLHF 的探索空间”，就是这个意思（[来源](https://arxiv.org/html/2604.25427)）。
- **RL 阶段保留 SFT 正则**：Seaweed 的 DPO 在正样本上加了 SFT loss（[来源](https://arxiv.org/html/2504.08685)）。
- **SFT 数据还能当 RL 的“真值参考”**：Kandinsky 5.0 图像 RL 拿 SFT 集里的真实图片和模型生成结果做比较（[来源](https://arxiv.org/html/2511.14993)）。
- 后续步骤见 [4.2 RL](#/post-rl)、[4.3 蒸馏](#/post-distill)、[4.4 OPD](#/post-opd)。

## 落地时最容易出问题的地方

| 问题 | 现象 | 对策 |
|---|---|---|
| 过拟合 | 提示词遵循变差、运动僵硬，画面趋同 | 早停；训练多个子模型再融合；混入一部分 CT 数据 |
| 运动退化 | 美学变好但结构崩、动作幅度小（Seaweed） | 专门收集复杂运动数据并人工挑选（Waver）；交给 DPO / RL 修复 |
| 风格被合成数据带偏 | 画面越来越“AI 感” | 控制合成数据比例，和真实数据平衡；人工一致通过才保留 |
| 类别塌缩 | 长尾主体（动物、文字、多人）效果变差 | 类别均衡；分领域 SFT 后融合 |
| caption 分布不一致 | 训练时用精修长 caption，推理时用户输入很短 | 配套 Prompt 改写器；训练时混入长短不同的 caption |
| 只看 loss 选 checkpoint | 评测效果和 loss 不一致 | 固定 prompt 集，做人工 GSB 评测，再加自动指标 |
| 融合失败 | 平均后画面模糊或出伪影 | 子模型必须同起点、学习率小；子模型之间差得太远时，减少参与融合的模型数 |

## 评估方法

| 方法 | 说明 | 例子 |
|---|---|---|
| 人工并排（GSB / 胜率） | 和 SFT 前的模型对比画质、运动、指令遵循 | Waver 304 条 prompt；Emu 对比 SDXL 的视觉胜率 |
| 分维度人工评分 | 画质、运动、对齐分开打分，防止一项提升掩盖另一项下降 | HunyuanVideo 1.5 的 GSB 三维度 |
| 自动指标 | VBench 类基准、VLM 打分、美学分 | 只能辅助判断，见 [第 5 章](#/reference) |
| 多样性监控 | 同一 prompt 换多个 seed，看生成结果之间的差异 | 用来提前发现过拟合 |
| 回归集 | 长尾类别、文字渲染、多人、复杂运动单独建 prompt 集 | 用来检查类别均衡是否生效 |

## 推荐流程

```flow
定类别体系 | 按风格、运动、主体、场景、镜头数分类，可参考 Seedance 的数百类
自动初筛 | 美学、清晰度、运动、转场、叠加物用严格阈值过滤，得到几十万到百万候选
均衡抽样 | 每类按配额抽样，用 kNN 补长尾
人工两级筛 | 通才初筛（重召回）→ 专家精筛（一致通过）；同时精修 caption
可选合成补充 | 少量美学或超现实合成数据，人工核验，并和真实数据平衡
分组 SFT | 同一起点，小学习率，每组若干千步，按人工评测早停
权重融合 | 均匀平均 5–10 个子模型，再做人工 GSB 评测
交给 RL | 融合后的 checkpoint 作为 DPO / GRPO 的参考策略
```

## 选型建议

- **资源少、想快速见效**：几千条严格人工精选数据（参考 Emu 和 Kandinsky 的规模），全参小学习率，训练 1 万步左右，开 EMA。
- **追求稳定的产品级模型**：按类别或领域拆数据，分别 SFT 后做 soup。几家公开报告都用了这一步，成本低、收益稳定。
- **后面接 RL**：SFT 适可而止，保留多样性。运动和结构问题交给 RL 修（参考 Seaweed、HunyuanVideo 1.5）。
- **I2V / 编辑 / 参考类任务**：按任务分开做 SFT 或保证任务均衡（HunyuanVideo 1.5、Kling-Omni），caption 写成相对首帧或参考的指令式。
